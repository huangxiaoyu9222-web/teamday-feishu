# 架构与数据边界

TeamDay v0.1 是本机运行的单团队应用。`app.py` 启动本地管理网页、定时检查线程，可选飞书官方 SDK 长连接。`teamday/core.py` 管理 SQLite 中的记录、待办、简报、行动、成果与投递状态。`connectors.py` 连接模型、RSS 和飞书 API；`web.py` 仅提供本地网页与同源 JSON API；`listener.py` 把飞书私聊发送者映射到已配置成员。

```text
录音豆／飞书转写（用户校准并粘贴） → 草稿 → 人工确认 → SQLite 知识
                                                      ↓
RSS 候选 → 校验 / 去重 → 个人关注匹配 → 每日简报 → 编号行动 → Markdown 成果
                                         ↑                         ↓
                              成员职责 + 个人待办          可选共享多维表格回写
```

## 知识与信任

每条现场记录保留原文、校正文、摘要、归属与可见范围。未确认草稿不进入简报上下文。模型建议不能自行确认；人名与说话人归属必须由用户检查。共享记录可进入团队成员的上下文，个人记录仅在该成员的领域服务和飞书私聊中出现。本地网页由可信管理员操作，可切换成员，并非员工登录入口。

模型执行以简报生成时的上下文快照为输入，执行前重新检查记录可见性。外部文本是资料，模型系统指令要求不把其中的指令当授权。成果先写本地 SQLite；可选多维表格回写单独报告。引用个人记录的成果不会自动写入共享表。

## 定时与失败

定时线程每 30 秒检查一次，默认关闭，工作日 08:00／13:00 且可修改。只有服务运行并在时刻后一小时内才发送。投递按成员、日期、时段和简报版本保存状态；成功的同一时段不自动重发。显式点击发送更新版本时可投递一次新版本。运行中断时不自动重试结果未知的发送。草稿生成可以重试，重复编号复用已完成成果。

## 范围

RSS / Atom 仅提供候选源和摘要，未核对正文事实。没有爬取通用网页或自动评估视频。飞书录音豆经飞书转写后的文本需要用户提供给本地入口；尚未从硬件或云文档直接采集。日历行动目前只生成议程与邀请草稿，不查询忙闲或发送邀请。知识库是本应用的 SQLite 记录，不是飞书 Wiki 自动同步。
