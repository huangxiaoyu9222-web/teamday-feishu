# 飞书接入：先发送，再接收数字回复

**简体中文** · [English](FEISHU.en.md)

需要有权创建企业自建应用的飞书账号，以及组织允许的应用发布、权限审批和使用范围。开通所需时间由组织流程决定。TeamDay 使用飞书中国站接口 `open.feishu.cn`，当前未提供国际版 Lark 域名切换。

## 1. 创建应用并启用机器人

在 [飞书开放平台](https://open.feishu.cn/app) 创建企业自建应用，添加机器人能力。在应用凭证页取得 App ID 和 App Secret，写入项目根目录 `.env`：

```dotenv
FEISHU_APP_ID=your_app_id
FEISHU_APP_SECRET=your_app_secret
```

这是占位示例。不要把真实凭证写进本文、截图或 GitHub。

## 2. 添加最小消息权限与事件

在权限管理中申请：

- `im:message:send_as_bot`：以应用身份发送消息。
- `im:message.p2p_msg:readonly`：接收用户发给机器人的单聊消息。

在事件与回调设置中，订阅「接收消息」事件 `im.message.receive_v1`，选择**使用长连接接收事件**。应用管理界面名称可能调整，具体权限与事件说明以官方 [发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create) 和 [接收消息](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive) 文档为准。

TeamDay 通过官方 Python SDK 建立出站 WebSocket，不提供 HTTP 公网回调地址。仅处理已绑定用户发给机器人的私聊文本，忽略群消息、语音、图片和文件。不必为本应用开放群聊读取范围。

创建并发布应用版本，确认相关成员在应用可用范围内，完成企业要求的审核或管理员启用。修改权限或事件之后也要检查变更是否已发布生效。仅保存后台配置不一定足够。

## 3. 安装 SDK 并建立长连接

以下命令在项目根目录运行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-feishu.txt
python3 app.py --live --feishu-listen --open
```

如果已经有虚拟环境，直接激活即可。模型执行还需要 `.env` 中的 `MODEL_API_KEY`、`MODEL_NAME` 和正确的 `MODEL_BASE_URL`，详见 [使用指南](USAGE.md)。

如果飞书后台要求先检测到活动长连接再保存订阅方式，保持上述进程运行，再回到事件配置页面保存。无需内网穿透。长连接监听和定时任务都依赖这个进程持续运行；电脑睡眠、退出终端或停止服务后不工作。

## 4. 获取并绑定成员 open_id

`open_id` 是**应用范围内的用户标识**；同一个人在不同应用中可能不同。不能用姓名、手机号、`user_id` 或其他应用的 `open_id` 替代。

可请管理员通过当前应用的官方 API 调试台和允许的通讯录接口获取成员 `open_id`；具体查询方式可能需要额外通讯录权限和数据范围，按所用接口说明申请。不要为了猜 ID 随意扩大权限。开发者也可在授权的消息事件调试环境中查看发送者的 `sender_id.open_id`。

本项目没有自动发现成员 ID 的页面，也不会在日志打印未绑定用户 ID；未绑定私聊会在监听层忽略。因此不要期待给机器人发一句话就自动注册。

打开本地「团队设置」，给对应成员填入获取的 `open_id` 并保存。确认姓名、角色、关注方向和 ID 配对正确。普通团队成员在飞书使用；本地页面提供给安装者 / 管理员，不是团队登录门户。

## 5. 先测试一次明确发送

1. 在本地真实模式选择测试成员。
2. 点击「更新早间简报」，核对内容。
3. 点击「发送简报到飞书」；这个按钮会向当前成员配置的 `open_id` 发送文本消息。
4. 在成员飞书客户端确认收到机器人私聊，再看页面的投递状态。

`sent` 表示飞书 API 已确认发送，不是对方已阅读。若返回 `failed`，核查应用凭证、机器人能力、权限、已发布版本、成员可用范围和 ID。遇到网络超时同时查看客户端，避免把未收到确认误判为一定没发出去。同一简报版本重复点击不会再生成相同投递；刷新生成新版本并明确点击发送时，可以发送新卡。

## 6. 用数字生成草稿

长连接开启后，已绑定成员可私聊机器人：

```text
早报
```

或 `简报`、`午报`。收到卡片后回复 `1`、`2` 等行动编号。想明确指定卡片时，使用返回消息中的卡片 ID：

```text
卡片ID 1
```

这只是格式示意，需替换成真实 ID。纯数字使用当前关联卡片；不要对过期或已更新替换的卡片继续操作。结果作为文本返回，并保存在本地「成果」中，可下载 Markdown。重复事件会复用已记录结果。

当前不会把任意自然语言请求作为命令执行，不会根据私聊中的成员名称替换发送者身份。更新现场记录、确认知识、修改团队设置在本地控制台操作。

## 7. 可选：成果写回多维表格

先让私聊生成流程正常工作，再启用此项。若成果使用了「仅本人」记录，系统不会将该成果自动写入共享表格。准备一张机器人应用有写入权限的飞书多维表格，创建以下 **5 个文本字段**，名称必须一致：

| 字段 | 写入内容 |
| --- | --- |
| 任务 | 行动标题 |
| 成员 | 配置中的成员姓名 |
| 状态 | 初稿待审 |
| 成果ID | 本地成果唯一 ID |
| 内容 | 成果文本，最多写入前 10000 个字符 |

在飞书权限管理中为创建记录接口开通所需的多维表格权限，并给应用相应文档访问和编辑权限。具体要求参见官方 [新增记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/create) 文档。权限申请与文档访问授权是两回事；有接口权限仍可能没有目标表格访问权。

填写并重启：

```dotenv
FEISHU_BITABLE_APP_TOKEN=your_bitable_app_token
FEISHU_BITABLE_TABLE_ID=your_table_id
```

这里的 app token 是目标多维表格标识，不是飞书应用的 App ID。回写失败会单独报告，本地成果仍然保留；不要把本地执行成功当作表格同步成功。这不是完整知识库双向同步。

## 8. 最后再开启定时投递

进入「团队设置」，开启定时发送，核对早间 / 午间时间、时区及仅工作日选项。默认示例时间是 `08:00`、`13:00`，时区 `Asia/Shanghai`。服务运行时才检查；计划时间后仅补发 1 小时内的任务，错过窗口不补发。每位成员每个日期时段最多尝试 3 次，自动失败重试至少间隔 5 分钟。

## 常见排查

| 现象 | 首先检查 |
| --- | --- |
| 演示无法发送 | 以 `--live` 启动；演示明确禁止外发 |
| 能发但数字无回复 | 是否加 `--feishu-listen`、安装 SDK、订阅事件并发布、绑定同应用 open_id |
| 连接看似正常却无事件 | 私聊权限、事件订阅、应用可用范围与发布状态 |
| 成果生成失败 | 模型地址、密钥、模型名、兼容响应格式；不要只看配置徽标 |
| 稍后重启没有补发早报 | 是否已经超过计划时间后的 1 小时窗口 |
| 表格无记录 | 回写结果、文本字段名、接口权限、表格访问权限和 token / table ID |

官方页面部分由客户端动态加载；若链接阅读器无法显示内容，请直接在浏览器打开，以当前开放平台控制台为准。
