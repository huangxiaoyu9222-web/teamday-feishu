# 使用 TeamDay

**简体中文** · [English](USAGE.en.md)

以下命令均在解压后的项目根目录执行。需要 Python 3.9 或更高版本；当前启动脚本使用 `fcntl` 进程锁，直接支持 macOS / Linux，Windows 请使用 WSL。

## 1. 不配置账号，先走一遍完整流程

```bash
python3 app.py --open
```

浏览器没有自动打开时，访问 `http://127.0.0.1:8765`。右上角会显示「演示模式 · 合成数据」。演示资料中的组织、人物和现场为虚构内容；生成行动使用本地模板，不调用真实模型，不发送飞书，也不抓取外部资讯。

1. 在右上角切换成员，看看不同角色的每日简报。
2. 在「交给助手推进」中执行编号，查看生成的草稿，再下载 Markdown。
3. 在「留给你的决定」中完成或暂缓待办。暂缓项在下一日重新开启。新现场记录默认仅本人可见，需主动选择团队共享。
4. 在「现场记录」填入组织、项目、参与者身份线索和原始转写；选择团队共享或仅本人。
5. 点击「整理并预览」，逐项校对原文、校正文本和摘要，按行填入待办；勾选核对确认后保存。
6. 回到「今日简报」，点击「更新早间简报」或「更新午间简报」，让新确认内容进入新的简报快照。

更新后请使用新卡片中的编号。已经送达飞书的旧卡片仍可用「卡片 ID＋编号」明确指定；未送达的旧卡片会失效。同一行动重复执行会返回已有成果，不重复生成。生成成功和多维表格回写是独立结果；回写失败不代表本地成果丢失。

按 `Ctrl+C` 停止服务。数据保存在项目的 `data/`，重新启动后仍在。端口冲突时可运行 `python3 app.py --port 8766 --open`；不要在同一模式同时运行多个实例。

## 2. 理解现场记录的边界

原始文本保留，校正不覆盖原文。身份应包含组织、职能和这次会谈中的角色；姓名相同不代表同一个人，「参与讨论」也不代表「拥有采购决策权」。拿不准的信息写明待确认。

真实模式且已配置模型时，预览会尝试提供校正与摘要建议；失败时保留原文供手工编辑。演示模式不调用模型，需要手工核对。建议不能替代人工确认。只有记录所有者能确认；确认产生的待办归确认人，不推断截止时间。

团队共享记录确认后可进入其他成员的简报上下文；仅本人记录按成员归属使用。这里的归属限制用于工作流，**不构成本地网页的用户登录权限隔离**。本机管理员能够切换成员。普通团队成员应通过飞书私聊使用。

## 3. 配置真实模式

macOS 可双击 `启动真实连接.command`：首次打开 `.env` 供你填写；再次启动自动创建虚拟环境、安装官方 SDK 并运行。首次安装需要联网和已安装的 Python。以下为手动配置方式。

复制环境示例（已有 `.env` 时直接编辑，勿覆盖）：

```bash
cp .env.example .env
```

在编辑器里填写这些环境变量，不要将真实值提交到仓库：

| 变量 | 用途 |
| --- | --- |
| `MODEL_BASE_URL` | 兼容接口的基础地址，例如 `https://api.openai.com/v1`；不要重复追加 `/chat/completions` |
| `MODEL_API_KEY` | 模型服务密钥 |
| `MODEL_NAME` | 该服务实际可用的模型标识，必须填写 |
| `MODEL_TIMEOUT` | 可选超时秒数，默认 60，代码限制为 10–180 |
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 飞书自建应用凭证 |
| `FEISHU_BITABLE_APP_TOKEN` / `FEISHU_BITABLE_TABLE_ID` | 可选成果回写表；不用时留空 |

模型接口调用 `POST {MODEL_BASE_URL}/chat/completions`，读取 `choices[0].message.content`。远程地址需要 HTTPS；本机回环模型可以 HTTP。模型供应商必须兼容这一请求和响应格式。页面显示模型「已配置」仅表示配置存在，实际可用性需执行行动验证。

只用本地工作台：

```bash
python3 app.py --live --open
```

需要飞书私聊接收数字指令：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-feishu.txt
python3 app.py --live --feishu-listen --open
```

飞书机器人配置步骤见 [飞书接入](FEISHU.md)。修改 `.env` 后重启服务。真实模式使用独立数据和 `config.json`，不会把演示客户资料混入真实团队。

## 4. 设置团队与信息源

「团队设置」可修改团队目标、成员姓名、角色、关注方向以及飞书 `open_id`。成员 ID 必须唯一，只能使用字母、数字、下划线、连字符；创建记录后尽量保持 ID 稳定。飞书 ID 必须属于当前应用，不能拿另一个应用的 ID 代替。

在「外部信息源」点击「添加来源」，填写名称与实际 RSS / Atom 地址，保存即可；不需要编辑 JSON。回到首页点击「刷新来源」。订阅源不等于通用网页搜索；按成员关注方向关键词匹配标题与摘要，不是语义检索。返回的是候选信息，不代表已核查事实，也没有自动分析视频。

## 5. 手动发送与定时发送

先在真实模式选择一位配置了 `open_id` 的成员，明确点击「发送简报到飞书」，在飞书客户端确认收到消息。页面展示的是投递接口状态；配置徽标不等于网络连接测试成功。

定时发送默认关闭。验证手动发送成功后，在「团队设置」勾选开启，设置早间、午间时间和 IANA 时区（默认 `Asia/Shanghai`），按需勾选仅工作日，然后保存。

工作日指周一至周五，不计算法定节假日。定时发送前会刷新来源与简报，避免沿用提前打开的旧快照。服务约每 30 秒检查一次；仅在计划时间后的 1 小时内补发，超过窗口不追发。电脑睡眠或程序退出时不会发送。失败有有限重试：每个成员、日期和时段最多 3 次，自动重试至少相隔 5 分钟；已经成功或结果不确定的发送不会盲目重发。同一简报版本重复点击不会重复发送；刷新生成新版本后，明确点击「发送简报到飞书」会发送这张新卡。定时任务在当天同一时段已成功送达时不自动重发。

## 6. 数据与分享

本地 SQLite 保存记录、简报、任务、成果和投递状态。模型执行时会将相关上下文发送给你配置的模型服务；飞书发送和可选表格回写会将相应内容传给飞书。服务只绑定本地回环地址，不提供团队登录、远程部署或公网访问方案。

发布 GitHub 或转交项目时，只分享干净源码与占位模板，排除 `data/`、`.env`、`config.json`、`config.demo.json`、`.venv/`。备份个人使用记录时应单独保存数据和配置，而不是混进公开源码包。

## 7. 当前不包含的能力

成果是 Markdown 文本草稿，不是已排版的 PPT 或 PDF。会议相关行动生成议程或邀请文案，不读取真实空闲时间，也不实际发邀请。现场记录接收已有转写，不接录音设备。暂不自动同步飞书知识库，不自动采集客户全部聊天，不代替你做采购、部署或对外承诺。
